# Лабораторная 2 по дисциплине "Технологии программирования"

**Вариант 7. Магазин бытовой техники.** Магазин ведет учет покупателей и
делает накопительную скидку, величина которой зависит от общей суммы
покупок любых товаров.

## Технологии
Python 3.12, Django 5.2 (MVC/MTV), PostgreSQL, pyyaml (фикстуры).

## Архитектура (MVC в терминах Django)
| MVC | Django | Файлы |
|---|---|---|
| Model | модели и бизнес-логика | `shop/models.py`, `shop/discounts.py`, `shop/services.py` |
| View | шаблоны страниц | `shop/templates/shop/*.html` |
| Controller | представления и маршруты | `shop/views.py`, `shop/forms.py`, `shop/urls.py` |

## Накопительная скидка
Скидка зависит от суммы, которую покупатель потратил ДО текущей покупки
(учитывается фактически уплаченная сумма):

| Потрачено, руб. | Скидка |
|---|---|
| от 10 000 | 3% |
| от 30 000 | 5% |
| от 60 000 | 10% |
| от 100 000 | 15% |

Покупатель идентифицируется по имени (модель `Customer`). Каждая покупка
хранит цену со скидкой и процент скидки на момент покупки.
Список покупателей: `/customers/`.

## Запуск локально
```
pip install -r requirements.txt
# PostgreSQL: база django_db, пользователь postgres
export DATABASE_PASSWORD=ps_password      # PowerShell: $env:DATABASE_PASSWORD="ps_password"
python manage.py migrate
python manage.py loaddata products.yaml
python manage.py test shop/tests/
python manage.py runserver
```

## Тестирование (лабораторная работа 3)
Используется встроенный в Django фреймворк `unittest` (`TestCase`,
`SimpleTestCase`, `TransactionTestCase`) и `unittest.mock`.

```
pip install -r requirements-dev.txt
python manage.py test shop/tests/ -v 2
coverage run --branch --source=shop --omit='shop/migrations/*,shop/tests/*' manage.py test shop/tests/
coverage report -m
```

| Файл | Что проверяется |
|---|---|
| `test_discounts.py` | чистая логика скидок: границы порогов, округление, неверные данные |
| `test_models.py` | поля и типы моделей, уникальность имени, свойство `discount_percent` |
| `test_services.py` | оформление покупки: накопление, скидка по уплаченной сумме, независимость покупателей |
| `test_services_isolated.py` | то же с моками (`mock.patch`): проверка взаимодействия модулей и отката транзакции |
| `test_forms.py` | валидация формы покупки |
| `test_views.py` | страницы, ошибки ввода, 404, сквозной сценарий набора скидки |
| `test_urls_admin.py` | маршруты и регистрация моделей в админке |
| `test_migrations.py` | перенос данных миграцией 0002 (старые покупки -> покупатели) |

Результат: 63 теста, покрытие кода `shop` 100% (с учетом ветвлений).

Качество тестов проверено «мутациями»: в код намеренно вносились 10 типичных
ошибок (`>=` -> `>`, смена процентов, `//` -> `/`, скидка по полной цене,
удаление транзакции и др.), каждая из них вызывала падение тестов.

## Выводы
В ходе лабораторной работы я изучил архитектурный шаблон MVC и разработал на Django веб-приложение магазина бытовой техники (вариант 7) с учётом покупателей и накопительной скидкой от 3% до 15%, зависящей от общей суммы прошлых покупок. Я освоил работу с PostgreSQL через ORM Django, миграции (в том числе с переносом существующих данных), загрузку данных из фикстуры, обработку и проверку форм, а также работу с Git
